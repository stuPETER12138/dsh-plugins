# 长期记忆 · Agent Memory

> 包名 `@local/dsh-agent-memory` · 版本 2.0.0

DSH 左侧栏里的长期记忆库。**默认什么都不注入**；你在对话里敲 `/memory <要回忆的内容>`，插件检索出最相关的几条，作为上下文随下一条消息送达模型。写入、清空、确认都由你决定，插件只负责检索和送达。

## 功能

- **零常驻注入**：不调用 `/memory` 时，记忆一个字都不进提示词。上下文开销为零，也不会因为改记忆而击穿提示词缓存。
- **指令调取**：`/memory 部署约定` 调取相关记录，**下一条消息**带上；`/memory clear` 清空；`/memory` 无参数看当前有多少条。
- **两条正交分类轴**：每条记录带 `kind`（语义 / 情节 / 过程）和 `subject`（我 / 机器 / 项目）。一条事实只存一次，检索按这两条轴过滤——避免"习惯"和"环境"两个文件夹各存一份、改一份忘一份。
- **三栏编辑页**：常驻画像（散文）、记录（增删改查 + 筛选）、待确认（相似记录合并 / 疑似矛盾）。
- **合并建议而不是自动合并**：同 kind、同 subject 的成对记录按字面相似度排队，≥0.8 标「几乎重复」，0.42–0.8 标「需要确认」；合并要你点，删除永远由你点。
- **可验证的环境事实**：记录可以带一条 `probe` 命令（如 `Get-Command rg`）。注入时会提示 agent「可用 `Get-Command rg` 确认」，让它可以先验证再用，而不是相信一条三个月前的记录。
- **中英界面**：文案随 DSH 界面语言切换。

## 为什么是"按需"而不是"每轮"

DSH 的系统提示词是**一次组装、作为一个 surface node 提交**的：改动它会从改动处开始让前缀缓存失效。而按需调取的内容走的是**动态上下文**（runtime context），追加在历史之后、只在变化时才写入一条快照——前面的缓存原样复用。

所以"默认不注入"不只是省 token，它同时解决了缓存问题。代价是：模型不会主动想起你，得你先说 `/memory`。

## 使用

1. 左侧栏点「记忆」，先在「常驻画像」里写几句硬约束（越短越好，它每次调取都排最前）。
2. 切到「记录」，给每条事实选 `kind` 和 `subject`，写内容；需要时填一条验证命令。
3. 在对话里敲 `/memory 上次那个部署方案`，命令提示「已调取 N 条记录，下一条消息会带上它们」。
4. 发出你的问题——那一轮的回答就能看到记忆。
5. 不想再带：`/memory clear`。

## 安装

完整的安装、升级与卸载步骤见 [docs/INSTALL.md](../docs/INSTALL.md)；**每个插件单独安装**。

1. **从本地文件夹安装（桌面端推荐、可离线）**：DSH Desktop 左侧栏「插件」→ 右上角「添加插件」→ 填本插件文件夹的**绝对路径** →「安装」→「立即启用」。
2. **从插件索引安装**：插件页「发现」标签 →「添加索引源」→ 填仓库的 `index.json` 地址 → 找到本插件 →「安装」→「立即启用」。
3. **命令行（`dsh` CLI profile）**：`dsh plugin --profile <profile> add "link:<本插件绝对路径>"`。

## 验证生效

- 插件页里本插件显示为已启用，没有「不可用」标记；
- 左侧栏出现「记忆」入口，三个页签都能打开；
- 写一条记录，保存后刷新页面仍在；
- 在对话里 `/memory <相关内容>`，再问一个相关问题，回答应当体现那条记录；
- 打开「待确认」，写两条意思相同的话，应出现「合并建议」。

## 工作原理

1. **存储**：`core.md`（散文）+ `records.jsonl`（一条一行 JSON）+ `dismissed.json`（不再提示的配对）。全部原子写，纯文本，可以直接用编辑器改。
2. **检索**：内存倒排索引 + BM25（ASCII 词 + 中文 bigram），再混入重要性与 90 天半衰的时间衰减，取前 6 条或约 1200 字。
3. **送达**：`ctx.systemPrompt.context()` 注册一个动态上下文；`/memory` 把检索结果放进「待送达」槽位，下一次组装提示词时取走一次（一次性，用完即空）。
4. **合并建议**：读取时实时计算同 `kind`+`subject` 记录两两的 Jaccard 相似度（记录超过 600 条时跳过扫描），不落库、不自动改数据。

## 数据与隐私

- 三个纯文本文件，只在本机读写，不联网、无遥测。
- 只有你敲 `/memory` 时，记忆内容才会进入请求；其余时间不占任何上下文。
- 记忆是"你说过的事"，不是安全边界：写进去什么，模型就会当成真的。别把来路不明的指令粘进记录。

## 配置

```yaml
- id: agent-memory
  name: '@local/dsh-agent-memory'
  config:
    dir: 'C:/dsh-memory'   # 默认 <harness home>/agent-memory
    maxChars: 8000         # 画像 / 单条记录的字数上限，500..50000
```

## 已知限制

- **不会自己写记忆**：从对话里自动抽取、去重、巩固都还没做；写入权在你手里。这也是它能保持干净的原因。
- **不会自动注入**：模型不会主动想起你，必须 `/memory`。这是有意的取舍。
- **没有语义检索**：BM25 + bigram 对「换个说法」的召回有限；记录量到几千条之前不值得上向量。
- **待确认是字面启发式**：只按字面相似度配对，真正的语义矛盾（"用 PowerShell" 和 "用 bash"）字面上并不相似，抓不到；那需要 LLM 判定。
- **`/memory` 需要支持斜杠命令的客户端**（DSH Web 可以）。
- **极简模式（minimal 预设）下不送达**：该预设会压制全部 runtime context，记忆到不了模型；需要记忆请用标准预设。

## 卸载

1. 在插件页卸载本插件。卸载**不会删除记忆文件**。
2. 要彻底清理，删除 `<harness home>/agent-memory/` 目录即可。
